# Kitout 2.6.0 Release Notes

Kitout 2.6.0 makes interruption reliable across the CLI, engine, and external
command process trees, while keeping the stable `version: 1` config schema from
earlier 2.x releases.

## Highlights

- `SIGINT`, `SIGQUIT`, and `SIGTERM` now cancel one process-scoped context shared
  by CLI commands, status checks, planning, execution, and interactive prompts.
- `status`, `apply`, `upgrade`, `doctor`, and `init` stop dispatching new work
  after cancellation.
- Interrupted planning or execution returns runtime exit code `3` and includes
  an explicit execution error in human-readable and JSON output.
- On Darwin and Linux, external commands run in managed process groups so
  cancellation includes descendants, including processes that outlive their
  original command leader.
- Interactive commands retain terminal access, and terminal suspend/resume
  restores foreground ownership correctly.
- Command cleanup bounds waits on inherited stdout and stderr pipes instead of
  allowing abandoned descendants to keep Kitout waiting indefinitely.
- The planner and executor now use `Resource.ID()` and `Resource.Type()` as the
  canonical identity for report items.

## Interruption Behavior

Pressing Control-C during a status check or apply now stops later resources from
starting. Remaining planned mutations are reported as not applied, and Kitout
returns runtime exit code `3` rather than treating interruption as a normal
resource failure.

The same behavior applies to managed Homebrew upgrades and doctor checks. An
interrupted doctor command reports the execution error separately instead of
claiming that a canceled prerequisite is missing.

Interactive Git, `chsh`, `sudo`, and configured shell commands can still use the
terminal while Kitout supervises their process group. If cancellation crosses a
privilege boundary or a descendant ignores the first signal, Kitout performs
bounded cleanup of the process group.

## Documentation

- Reworked the homepage around the first-run sequence: install, initialize,
  inspect, preview, and apply.
- Explained what each starter-config section causes Kitout to inspect or change.
- Clarified that relative config paths resolve from the selected config file's
  directory, not the shell's current working directory.
- Improved semantic labeling, keyboard behavior, and copy-button feedback.
- Added an asdf Node.js setup example.
- Corrected the README starter config to contain a single `brew.taps` key.

## Compatibility

- No schema version bump is required; this is an additive `version: 1` release.
- Existing `2.5.0` configs continue to load without required changes.
- Status checks and dry-runs still do not change the system.
- Risky apply actions still require confirmation unless `--yes` is passed.
- Kitout still does not install Homebrew automatically.
- Cancellation is a runtime error (`3`); resource-specific apply failures remain
  partial apply failures (`4`).

## Distribution

The tagged release workflow publishes:

- `kitout_2.6.0_darwin_arm64.tar.gz`
- `kitout_2.6.0_darwin_amd64.tar.gz`
- `kitout_2.6.0_checksums.txt`

Homebrew tap installation should use the checksums from the exact GitHub release
assets.

## Install

```sh
brew tap vwall/kitout
brew install kitout
```
