# Kitout 1.1.0 Release Notes

Kitout 1.1.0 adds two optional resource types to the stable `version: 1`
config schema: file and directory copies, and current-user login shell
management.

## Highlights

- Copy files or directories from a setup repo into local destinations with the
  new `copies` config section.
- Manage the current user's macOS login shell with the new `login_shell` config
  section.
- Preview copy and login-shell changes with `kitout apply --dry-run`.
- Keep risky actions confirmation-gated: copy replacements and login-shell
  changes require confirmation unless `--yes` is passed.

## New Resources

### Copies

`copies` manages a physical copy of a file or directory:

```yaml
copies:
  - source: ./codex/skills/nuxt-practices
    target: ~/.codex/skills/nuxt-practices
    replace: false
```

Copy sources must be regular files or directories. Symlinked sources are
rejected so status and apply behavior stay explicit. Existing differing targets
are reported as failed unless `replace: true` is configured.

### Login Shell

`login_shell` manages the current user's macOS login shell:

```yaml
login_shell:
  path: homebrew:fish
  add_to_etc_shells: true
```

The `path` field accepts either an absolute path or `homebrew:<binary>`, which
resolves through `brew --prefix`. When `add_to_etc_shells` is true, Kitout can
append the resolved shell path to `/etc/shells` before running `chsh`.

## Compatibility

- No schema version bump is required; this is an additive `version: 1` release.
- Existing `1.0.0` configs continue to load without changes.
- Status checks and dry-runs still do not change the system.

## Distribution

The tagged release workflow publishes:

- `kitout_1.1.0_darwin_arm64.tar.gz`
- `kitout_1.1.0_darwin_amd64.tar.gz`
- `kitout_1.1.0_checksums.txt`

Homebrew tap installation should use the checksums from the exact GitHub release
assets.

## Install

```sh
brew tap vwall/kitout
brew install kitout
```
