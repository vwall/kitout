Status before action

Kitout names satisfied, missing, changed, failed, and skipped resources before applying changes.

Dry-run as default habit

The plan view makes the next run inspectable, including paths and resource identifiers.

Receipts for reruns

Every check and apply result can be read in terminal logs without relying on color alone.

New machines drift when setup lives in memory.

  • New Mac setup takes hours
  • Shell scripts become fragile
  • Dotfiles only solve part of the problem
  • Team onboarding drifts over time

Kitout reconciles the machine with the file.

  • Desired state in YAML
  • Dry-run before changes
  • Visible reconciliation plan
  • Safe application of changes

Safety is visible, not promised after the fact.

  • Dry-run first
  • Human-readable plans
  • Helpful failures
  • No hidden magic
  • Predictable behavior

Why this direction works

Infrastructure visual language plus native-window polish makes Kitout feel dependable enough to inspect a real developer machine.
